--------------------------------------------------
30. ACTIVITÉS LIÉES AUX DESTINATIONS
--------------------------------------------------

IMPORTANT :

Les activités ne doivent PAS être considérées comme un catalogue indépendant dans la V1.

Une activité touristique est d'abord une activité DISPONIBLE DANS UNE DESTINATION.

Chaque destination possède donc ses propres activités.

Exemples :

ÎLE DE GORÉE
→ Kayak
→ Jet-ski
→ Pirogue
→ Visite culturelle
→ etc.

LAC ROSE
→ Balade à chameau
→ Équitation
→ Quad
→ Balade en pirogue
→ etc.

SALY
→ Jet-ski
→ Quad
→ Pirogue
→ activités nautiques
→ etc.

--------------------------------------------------
31. GESTION DES ACTIVITÉS PAR L'ADMIN
--------------------------------------------------

L'administrateur doit pouvoir associer les activités aux destinations.

Dans l'administration :

DESTINATION
↓
"Activités disponibles"

Exemple :

Île de Gorée

☑ Kayak
☑ Jet-ski
☑ Pirogue
☐ Quad
☐ Chameau

L'administrateur peut :

- ajouter une activité ;
- retirer une activité ;
- modifier une activité ;
- modifier son prix ;
- modifier sa disponibilité ;
- modifier sa description ;
- ajouter des images ;
- ajouter une vidéo ;
- définir une durée ;
- définir une capacité ;
- définir les conditions ;
- définir l'âge minimum si nécessaire ;
- définir les périodes disponibles.

--------------------------------------------------
32. ACTIVITÉS DANS LE SIMULATEUR
--------------------------------------------------

Lorsqu'un client ajoute une destination à son voyage,
le système doit automatiquement rechercher les activités associées à cette destination.

Exemple :

Client ajoute :

ÎLE DE GORÉE

Le système affiche :

"QUE VOULEZ-VOUS FAIRE À GORÉE ?"

Puis les activités disponibles.

Le client peut sélectionner celles qu'il souhaite.

--------------------------------------------------
33. EXPÉRIENCE DE SÉLECTION DES ACTIVITÉS
--------------------------------------------------

La sélection des activités doit rester ludique.

Ne pas afficher un simple tableau.

Utiliser des cartes visuelles.

Exemple :

┌─────────────────────────────┐
│          IMAGE              │
│                             │
│ 🛶 KAYAK                    │
│                             │
│ Explorez les environs       │
│                             │
│ 15 000 FCFA                 │
│                             │
│ [+ AJOUTER]                 │
└─────────────────────────────┘

Lorsqu'une activité est sélectionnée :

[✓ AJOUTÉ]

avec une animation.

Le prix du voyage est immédiatement recalculé.

--------------------------------------------------
34. ACTIVITÉS OPTIONNELLES
--------------------------------------------------

Les activités ne doivent jamais être obligatoires sauf si
l'administrateur configure explicitement une activité comme incluse/obligatoire.

Par défaut :

Destination
+
Activités optionnelles

Le client choisit librement.

--------------------------------------------------
35. ACTIVITÉS PAR DESTINATION
--------------------------------------------------

Une activité peut être disponible dans plusieurs destinations.

Exemple :

PIROGUE

→ Île de Gorée
→ Lac Rose
→ Saly
→ autre destination

Mais chaque association destination/activité peut avoir :

- prix différent ;
- durée différente ;
- disponibilité différente ;
- capacité différente ;
- description différente ;
- conditions différentes.

Créer donc une relation spécifique entre :

DESTINATION
et
ACTIVITÉ.

Ne pas simplement mettre destination_id directement dans l'activité si cela empêche une activité d'être utilisée dans plusieurs destinations.

--------------------------------------------------
36. ACTIVITÉS ET BUDGET
--------------------------------------------------

Le prix des activités doit être intégré au moteur de budget.

Exemple :

Voyage :

Dakar
3 nuits

Gorée
2 nuits

Lac Rose
3 nuits

Activités :

Kayak
15 000 FCFA

Jet-ski
30 000 FCFA

Chameau
10 000 FCFA

Quad
20 000 FCFA

Le simulateur calcule automatiquement :

Transport
+
Hébergement
+
Activités sélectionnées
=
Budget estimé

Pour la V1, si les prix d'hébergement et de transport ne sont pas encore intégrés au nouveau simulateur, prévoir une architecture permettant leur intégration ultérieure.

--------------------------------------------------
37. ACTIVITÉS DANS L'ITINÉRAIRE
--------------------------------------------------

L'itinéraire doit pouvoir afficher les activités choisies.

Exemple :

📍 Île de Gorée
2 nuits

Activités :

🛶 Kayak
🌊 Jet-ski

↓

📍 Lac Rose
3 nuits

Activités :

🐪 Chameau
🏍️ Quad

Le client doit pouvoir modifier les activités sans supprimer la destination.

--------------------------------------------------
38. ADMINISTRATION — VUE DESTINATION
--------------------------------------------------

Dans l'admin, créer une gestion centralisée :

DESTINATION
│
├── Informations
├── Photos
├── Vidéos
├── Description
├── Informations pratiques
├── Activités
├── Disponibilité
└── Paramètres

La section "Activités" doit permettre à l'administrateur de gérer directement les activités disponibles dans cette destination.

--------------------------------------------------
39. DISPONIBILITÉ DES ACTIVITÉS
--------------------------------------------------

Une activité peut être :

🟢 Disponible
🟠 Disponibilité limitée
🔴 Indisponible

L'administrateur doit pouvoir modifier cet état.

À terme, la disponibilité pourra dépendre :

- de la date ;
- du nombre de personnes ;
- de la capacité ;
- de la saison ;
- des réservations existantes.

Le client ne doit jamais pouvoir sélectionner une activité qui est réellement indisponible.

--------------------------------------------------
40. FUTURE ÉVOLUTION
--------------------------------------------------

Cette architecture doit permettre plus tard d'ajouter :

- réservation instantanée ;
- créneaux horaires ;
- activités privées ;
- activités de groupe ;
- guide ;
- équipement ;
- transport jusqu'à l'activité ;
- réservation d'activités ;
- disponibilité en temps réel.

Mais ces éléments ne doivent pas complexifier inutilement la V1.

--------------------------------------------------

--------------------------------------------------

Cette fonctionnalité doit être intégrée dans :

MCD
MLD
MPD

et dans les traitements :

MCT
MOT

CLIENT

DESTINATION

ACTIVITÉS DISPONIBLES
↓
ACTIVITÉS SÉLECTIONNÉES

BUDGET

--------------------------------------------------
42. RÈGLE PRODUIT
--------------------------------------------------

Le client ne choisit pas d'abord :

"Je veux faire du kayak."

Puis cherche où le faire.

Dans la V1, le parcours principal est :

"Je veux aller à Gorée."

↓

"Qu'est-ce que je peux faire à Gorée ?"

↓

"Je choisis mes activités."

↓

"Je continue mon voyage."

Le système doit donc être pensé autour de :

DESTINATION → ACTIVITÉS DISPONIBLES → CHOIX DU CLIENT.
